# Реверс-прокси на Nginx

[English](README.md)

Скрипт настраивает VPS, который принимает запросы к вашему домену и
передаёт их серверу с сайтом. Nginx работает как реверс-прокси, а Certbot
получает и продлевает сертификат для HTTPS.

## Что подготовить

- Чистый VPS с Debian 12, Debian 13, Ubuntu 22.04 LTS или Ubuntu 24.04 LTS
  и systemd. Нужен доступ по SSH с правами root или `sudo`. Если на VPS уже
  есть собственные конфиги Nginx, установщик остановится.
- Узнайте публичный IP VPS. В панели DNS направьте **A**-запись домена
  на IPv4-адрес VPS. Оставляйте **AAAA** только если IPv6 работает и запись
  указывает на VPS. Для `www` создайте отдельную запись с адресом VPS или
  CNAME на основной домен. Если провайдер DNS предлагает проксирование,
  используйте для этих записей режим «только DNS».
- Откройте входящие TCP-порты **80** и **443** в панели хостинга и в
  файрволе на VPS, если он включён. Порт 80 понадобится и для продления
  сертификатов.
- Подготовьте адрес сервера, на котором уже работает сайт. Он должен
  быть доступен с VPS и отдавать сайт при запросе с публичным именем
  домена. Например, веб-приложение может слушать
  `http://192.0.2.20:8080`.

## Установка и первый сайт

Выполните команды на VPS по SSH. Если вошли как root, уберите `sudo`.
Если Git уже установлен, пропустите первую строку.

```sh
sudo apt update && sudo apt install -y git
git clone https://github.com/NikKurkov/nginx-reverse-proxy.git
cd nginx-reverse-proxy
sudo ./install.sh
sudo nginx-reverse-proxy add
```

Введите домен без `https://`, адрес сервера с сайтом и email для аккаунта
Let's Encrypt. Проверьте введённые данные и подтвердите запуск клавишей
`y`. Скрипт проверит, что по каждому адресу из DNS доступен тестовый
запрос по HTTP. После выпуска сертификата включится перенаправление на
HTTPS.

Откройте сайт в браузере или проверьте его со своего компьютера:

```sh
curl -I https://example.com/
```

Подставьте свой домен. Вы должны получить ответ от сайта. Если сервер
не обрабатывает HEAD-запросы, откройте сайт в браузере или запустите
`curl https://example.com/`.

## Как добавить следующие сайты

Для запуска без вопросов передайте нужные параметры и `--yes`. Ключ
`--www` добавит `www.example.com` в конфиг Nginx и в тот же сертификат.

```sh
sudo nginx-reverse-proxy add example.com \
  --origin http://192.0.2.20:8080 --email admin@example.com --www --yes
```

Чтобы каждый раз не вводить адрес сервера или email, заполните
`origin=` или `email=` в файле `/etc/nginx-reverse-proxy/defaults`
через `sudoedit`. Параметры команды имеют приоритет. Настройки
применяются при добавлении следующих сайтов.

Если сервер сайта принимает HTTPS, укажите его HTTPS-адрес. Nginx
проверит сертификат по списку доверенных центров на VPS. При подключении
по IP укажите через `--tls-name` имя из сертификата сервера:

```sh
sudo nginx-reverse-proxy add example.net \
  --origin https://192.0.2.20:8443 --tls-name origin.example.net \
  --email admin@example.net --yes
```

В адресе сервера можно указать имя хоста или IP и порт. IPv6-адрес
заключите в квадратные скобки. Вводите адрес без пути, параметров и
учётных данных. Nginx передаст серверу путь запроса и публичное имя домена.

Чтобы добавить несколько сайтов с одним адресом сервера, запишите их
в `domains.txt`, по одному домену на строку. Пустые строки и текст после
`#` пропускаются.

```sh
sudo nginx-reverse-proxy add --file domains.txt \
  --origin http://192.0.2.20:8080 --email admin@example.com --yes
```

Если имя записано с ошибкой или повторяется, скрипт остановится до
добавления сайтов. Если ошибка возникнет позже, например при проверке DNS
или выпуске сертификата, уже добавленные сайты продолжат работать.
Исправьте причину и повторите команду для оставшихся доменов.

## Список сайтов и отключение

```sh
sudo nginx-reverse-proxy list
sudo nginx-reverse-proxy remove example.com
```

Команда `remove` отключает сайт в Nginx и сохраняет конфиг и сертификат.
Для проверки при продлении Certbot требуется включённый сайт. Пока сайт
отключён, сертификат может истечь.

Конфиги сайтов лежат в `/etc/nginx/sites-available/` и называются
`reverse-proxy-ДОМЕН.conf`. Чтобы вернуть отключённый сайт, администратор
может восстановить ссылку на конфиг в `/etc/nginx/sites-enabled/`,
проверить конфигурацию командой `sudo nginx -t` и перечитать её через
`sudo systemctl reload nginx`. Перед использованием сайта проверьте срок
действия сертификата. Команда `add` не перезаписывает сохранённые конфиги.

## Если что-то не получилось

| Что происходит | Что проверить |
| --- | --- |
| Не проходит проверка DNS или HTTP | Проверьте A и AAAA для каждого указанного имени, включая `www`. Дождитесь обновления DNS. Проверьте порт 80 и доступность публичного IP VPS с самого VPS. |
| Не выпускается сертификат | Посмотрите вывод Certbot и `/var/log/letsencrypt/letsencrypt.log`. Проверьте DNS, доступность порта 80 из интернета и записи CAA, если они есть. |
| Сайт отвечает 502 | Проверьте с VPS адрес и порт сервера сайта. Для HTTPS проверьте цепочку сертификата и имя, которое передали в `--tls-name`. Подробности есть в `/var/log/nginx/error.log`. |
| HTTPS работает, сертификат не продлевается | Домен должен по-прежнему указывать на VPS, а порт 80 должен быть открыт. Проверьте `systemctl status certbot.timer` и запустите `sudo certbot renew --dry-run`. |

При ошибке добавления скрипт удаляет новый конфиг и перечитывает прежнюю
конфигурацию Nginx. Если Certbot уже успел выпустить сертификат, он
сохранится для повторной попытки.

## Проверка скрипта

`bash tests/check-cli.sh` проверяет справку и разбор аргументов. Если есть
Docker и OpenSSL, запустите `bash tests/smoke.sh debian:12-slim`. Этот тест
поднимает Nginx, Certbot и локальный ACME-сервер в отдельной сети и
использует тестовый центр сертификации.
